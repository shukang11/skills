# Fix root causes

调试时读。修产生点，不修症状。

## 判据

- **先复现**。复现不出来就不改业务代码，先把复现做出来，做法见 `diagnosing-bugs`。
- **一路问为什么**，问到根因再动手。中途停下，修的就是最近一层症状。
- **不加 guard**。给空指针加 nil 检查、给越界加 try/catch，是消音。错误被挪走了，产生点还在。
- **一段注释才解释得清的 workaround，说明代码是错的**。改代码，不改注释。
- **查模式，不查实例**。同一个错误往往在别处也写着。按模式 grep 一遍，能一起修就一起修，修不完的列出来。
- **卡住就上仪器**。日志、真实报错、断点，不猜。
- **"重启之后就好了"先怀疑持久状态**：配置文件、缓存、锁文件、序列化下来的状态。清掉某个状态文件就恢复的，把状态校验作为修法。

## 收工

- 回复里写明产生点在哪、症状点在哪、同一模式还有几处在别处。
- 留了 guard 的，说明它挡的是一个不可能发生的状态，还是只是把报错挪走了。
- 同一模式的其余实例没修的，写成待办，不写成"已修复"。
