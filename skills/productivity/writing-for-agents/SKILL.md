# Writing for Agents

编写任何供 Agent 消费的文档（技能定义、`AGENTS.md`、规范文档）的元心法。
核心目标：**确保 Agent 每次执行都能走出稳定、高质量的过程路线，而不是依赖随机的悟性。**

## 两种负荷预算（The Two Loads）

你新增的每一份文档或指针，都在消耗两种预算之一：
- **上下文负荷（Context Load）**：每轮会话常驻消耗的 Token 和注意力（如 `AGENTS.md`、常驻技能描述）。无论是否触发都在扣减预算，因此常驻描述必须极度精简、惜字如金。
- **认知负荷（Cognitive Load）**：由人类判断何时选用哪个工具/文档的心智成本。

**指针原则（Context Pointers）**：
- 技能描述（Description）本质上是一个上下文指针；
- **首词触发（Front-load leading words）**：把最重要的触发动词和场景词置于开头；
- **一分支一触发**：禁止用同义词堆砌重复触发条件。

## 信息阶梯与渐进式披露（Information Hierarchy）

文档内容应按 Agent 需要的紧迫程度分层：
1. **主流程步骤（In-file Steps）**：核心操作步骤，按顺序排列；
2. **就地参考（In-file Reference）**：当场查阅的规则、反例与定义；
3. **披露参考（Disclosed Reference）**：非核心、低频的展开细节，拆分至独立子文件，用指针按需加载。

**反蔓延（Sprawl）**：
文档过长会导致 Agent 注意力稀释。长文档必须依靠渐进式披露，将大篇幅的背景知识与复杂边缘案例剥离到单独的参考文档中。

## 完成判定标准（Completion Criteria）

每个核心步骤必须拥有明确的收工判定卡尺：
- **清晰性（Clarity）**：Agent 能否明确区分“已完成”与“未完成”？模糊的表述（如“梳理清楚了”）会引发**过早完工（Premature Completion）**的坏习惯。
- **高要求（Demand）**：“列出所有修改的模块”比“给出一个变更清单”更具强约束力。

## 引导词工程（Leading Words）

充分利用大模型预训练中固有的高权重工程概念，用单个词激活大片行为：
- 用 *tight*（紧凑的）、*red*（飘红的）替代一段关于“快速、确定性、低开销、可验证”的长篇描述；
- **肯定式引导（Prompt the Positive）**：告诉 Agent“该怎么做”，尽量避免“千万别怎么做”（否定句容易将禁止的行为拉入注意力和高频激活区）。
