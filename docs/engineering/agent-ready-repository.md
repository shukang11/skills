## Agent-ready Repository 设计说明

本技能回答的不是"文档齐不齐"，而是：**能力够了之后，人为什么仍然被嵌在循环里。**

它审计的对象是**仓库作为一个工作环境**——入口、权威来源、目录边界、工作流、模板、验证——外加一个新维度：**人在哪里被迫出手**。产出是一张**逐条可裁决的建议表**，然后停住。

> 它属于「项目治理」层，不修 bug、不写功能、不改代码结构。前者是 `codebase-design` 与 `code-review` 的领地。
>
> 和 spec-anchor 的分工：spec-anchor 的周期审查与 `code-review` 审的是**改动**（一段 diff）；本技能审的是**环境**（零上下文能不能走通、人在哪出手）。在已接入 spec-anchor 的项目里，`init` 已铺的原则与规则不再重复建议，转而检查它们是否真的接上（`references/spec-anchor-projects.md`）。本技能不依赖 spec-anchor，因此留在个人库、不随引擎同捆。

### 1. 核心立场

> **上限 = 现实能自己回话的程度；回不了话的那部分，署你的名。**

早期版本把它压成"上限 = 仍要你亲自注意的时刻"，但那个说法把天花板永久钉死在"人"身上。反例就在来源访谈里：如果证明系统能兜住正确性，那一刻的瓶颈是**证明系统**，不是人。

所以技能的目标不是"把人拿掉"，而是：

- **能把结果自己报回来的**，想办法让事情自己报（造眼睛）；
- **能预先消灭错误选项的**，让默认路径上只剩一种做法（收窄路）；
- **两者都做不到的**，明确承认它必须由人来担，并记在账上。

### 2. 三出口门禁（本技能的核心机制）

每条建议**必须挂到一个出口**。门禁要求的是"有出口"，**不是"必须是出口①"**。

| 出口 | 机制 | 形式 |
| --- | --- | --- |
| ① 造眼睛 | 错误能被**会跑的检查**捕获 | lint / test / CI / 只读守卫 |
| ② 收窄路 | 错误选项在**默认路径上消失** | 模板 / 目录约定 / 脚手架 / 唯一写法 |
| ③ 人侧记账 | 无法机械验证，**明确划给"必须人来"** | 写清落在哪个动作上 |

**为什么必须允许出口③**：把不可机械验证的项硬塞成坏检查是反效果——只会增加噪声，并制造"已验证"的假象。强迫"每条都必须自动化"，产出的是一堆没人信的门禁。

### 3. 两遍零上下文基线

同一个代表任务，观察两次：

- **第一遍 · Agent 侧**：不给历史对话、不给正确路径，看它能否独立完成、卡在哪、会不会危险操作。观察对象是**环境**，不是那个 agent。
- **第二遍 · 人侧**：换到人这一侧，看**人在哪里被迫出手**。产出只分两桶：`能离开人的` / `不能离开人的`。

**第二遍的硬约束必须写死**：必须有真人在环；人不在时记「缺源」并跳过，**严禁由 Agent 模拟"人会在哪里出手"**。这是本技能最大的幻觉源——模型很容易编出一份听起来合理的"人类摩擦清单"。

一个容易搞反的点：**不是所有人工注意点都该消灭。** 有些缓冲迫使人看清全局，属于有意保留，应记到出口③而不是当缺陷修。

### 4. 为什么止于建议

技能不执行整改、不代排优先级、不生成"下一步 3 件事"。

理由：**它的职责是把决策变便宜，不是替人做决策。** 交付表的每条建议都带「接受代价」列——写清接受它要付出什么（新增哪个脚本、每次改动多几步、谁需要记住什么）。写不出具体代价的，说明这条建议还不具体，退回重写。

裁决列**留空**，由人和 AI 逐项目、逐条填「接受 / 驳回 / 待议」。技能不预填、不给倾向。

### 5. 边界：不做价值判断

明确排除：**"这个项目还该不该继续""精力配比对不对"**。

那是价值判断，依据是项目台账的活跃度与精力数据，不是仓库结构。塞进本技能会让它从"审计"滑向"裁决"，违反第 4 条。它归项目台账与组合方法论，不归这里。

### 6. 思想来源

本技能的判断层来自 Lauren Tan（pstack 作者）关于"退出人肉传感器"的实践。三处直接对应：

| 她的做法 | 本技能的落点 |
| --- | --- |
| *"I was the meat proxy between my agent and Chrome DevTools"* | 审计对象从"agent 干得好不好"扩展到"人还被卡在哪" |
| 验证技能让 agent 自己跑、自己点、自己抓 trace | 出口①：造眼睛 |
| 逐次把失败收成 lint / 约定 / 唯一写法 | 出口②：收窄路 |
| *"sometimes having a buffer forces you to think about the big picture"* | 出口③：**主动保留**的人工注意点，不是缺陷 |

完整的访谈依据与落地对照见个人知识库 `02-知识库/阅读笔记/pstack访谈-信任阶梯与软件厨房.md`。

### 7. 已知软点

- **出口③ 是兜底口**：理论上可以把所有建议都标 ③ 而通过门禁。已收紧：SKILL.md 的完成判据要求每条 ③ 写明落在哪个人的关口动作上，并说明为什么归不进①或②。仍是自述，没有机检，下一轮实测时看是否还有整表标 ③ 的情况。
- **人侧基线依赖人在环**：无人可观察时技能只能产出"缺源"，那一条链的价值归零。这是设计取舍，不是缺陷。
- **仓库结构高度依赖语义**：所以它不产出自动重构补丁，结构变化仍需人类确认。
