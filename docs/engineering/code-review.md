## 代码审查（Code Review）设计说明

本技能基于 Matt Pocock 的双轴审查架构，针对单人本地开发体验做了无网络依赖的收敛。

### 核心设计哲学：双轴独立（Two Axes）
- **规范不能遮掩功能缺失**：漂亮的坏功能依然是 Bug；
- **功能不能纵容架构腐化**：跑通了但散发着浓烈坏味道的代码会破坏可维护性。

### 本地化改进：
1. **脱离外部 Issue Tracker**：直接对齐本地 `to-spec` 产生的 `.agents/notes/proposed/` 或 `docs/` 规范文件；
2. **坏味道基线内置**：开箱即带 8 种高频 Martin Fowler 代码坏味道诊断，即便项目未提供单独的 Lint/规范文件也能给出高质量架构反馈。
