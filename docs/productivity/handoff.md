## Handoff — 会话状态交接胶囊（设计档案）

`handoff` 的本质不是文本总结或压缩，而是**一份临时恢复胶囊（Recovery Capsule）**：在会话被迫中断时，把「我停在哪、状态如何、下一步是什么」压缩成一份可被下一个 Session 直接消费的文件。

---

## 1. 当前定位

| 维度 | 结论 |
| :--- | :--- |
| **主场景** | Session 续聊 / 被迫中断（上下文将满、任务中途收工、甩掉包袱保留线程） |
| **目标读者** | 同一个任务的下一个 Session |
| **载体** | `/tmp/handoff-<task-slug>-<timestamp>.md`（临时耗材，非项目资产） |
| **前提** | standalone，不要求事先存在笔记 |
| **不负责** | 跨角色编排（Planner → Worker 的任务派发），需另用专用技能 |

**核心设计约束：** 交接是一次性、不可交互、单向的。用户交出去之后就不在场了，文档成为唯一真相来源。因此第一性原理是——

> **在用户不在场的情况下，最小化接收方犯错的概率。**

这条约束解释了本技能后续所有的纪律选择：宁可短、准、带标签，也不追求文档完整度。

---

## 2. 设计决策记录

### [2025] 定位从「可移植性」转向「A/C 中断恢复」

**背景**

本技能最初的设计文档将其定位为「购买可移植性（Portability）」，场景矩阵为：更换 Harness、分支分流、跨仓库跳跃、人类异步交接。

**问题**

上述场景全部是**低频事件**（跨 Harness 迁移一年几次）。而本技能在仓库矩阵中与 `code-review` 并列，实际用途是**日常会话流转**（每天发生）。用低频场景定义技能行为，会导致它对最高频的用法不适用。

具体失配点：原设计假设调用者**已知下阶段目标**（`argument-hint` 问「下一个会话的核心目标是什么？」）。但被迫中断时，用户恰恰是在交出控制权的那一刻才停止思考的——**他并不知道目标是什么。**

**决策**

以 A/C（被迫中断）为默认场景重新定义技能行为。可移植性仍成立，但降级为附带属性，不再作为设计出发点。

**放弃的选项**

| 选项 | 放弃理由 |
| :--- | :--- |
| 保持 Portability 定位 | 为低频场景优化，高频场景体验差 |
| 把 Planner → Worker 一并纳入 | 那需要任务包、验收标准、输入输出契约，会把这个技能拖重；Goal 常为 Pending 与「必须明确」的需求直接冲突 |
| 强制要求先写笔记 | 中断是突发事件，来不及走前置流程 |

**后果**

引出了三条新纪律（No Fabrication、Self-Audit）和骨架重构（中断点置顶、Verify First 前置）。

### [2025] 新增 No Fabrication 纪律

**背景**

原有 `Facts vs. Assumptions` 要求标注 `[Verified Fact]` / `[Pending]`。但它管的是**已写内容的定性**，没管**是否该写**。

**问题**

被迫中断时，让模型去回忆「我们当时为什么否决了方案 B」，极易触发幻觉——而这类错误被当成 `[Verified Fact]` 采信后危害最大，因为接收方无法交叉核对。

**决策**

新增独立纪律：会话内无明确记录的内容不写。**空缺本身就是有效信息。** 针对下阶段目标、否决理由、卡点根因三类高危字段，无记录时显式写「无明确记录」，严禁推断补齐或事后合理化。

**放弃的选项**

| 选项 | 放弃理由 |
| :--- | :--- |
| 合并进 Facts vs. Assumptions | 两者是不同问题：前者管标签，后者管产出，混在一起会弱化任一方的执行力 |
| 允许「合理推断」但加标注 | 接收方倾向于采信确定性陈述，标注不足以对冲风险 |

---

### [2025] 骨架引入「中断点」与「Verify First」

**背景**

原骨架顺序为：Goal → Anchors → Decisions → Runtime State → Directives。

**问题**

1. 缺「我在时间轴上的哪个位置」。接手方知道「下一步做什么」，但不知道为什么是这一步。
2. Goal 被放在最权威的位置（标题正下方），而它恰恰是最不可靠的字段（常由 Agent 推断）。
3. Directives 直接跳到「建议启动 /tdd」，但中断场景下第一步应该是**先搞清楚现状**。

**决策**

1. 新增 `1. 中断点 (Where I Left Off)` 并置顶，含最后完成的操作、未完成项、原计划的下一步、工作区状态（分支 / 未提交改动）。
2. Goal 与中断点并列，强制可靠性标签：`<用户明示>` 或 `[Pending / Unverified] <推断>`。
3. Directives 拆为三段：**Verify First**（先跑命令复验 `[Verified Fact]` 是否仍成立）→ **Immediate Next Step** → **Suggested Skills（可选）**。

**放弃的选项**

| 选项 | 放弃理由 |
| :--- | :--- |
| 保持原顺序，仅补充说明 | Goal 置顶的结构性误导无法靠文字消解 |
| Verify First 写在正文而非骨架 | 骨架是执行清单，写进骨架才会被照做 |

**补充说明：Verify First 的副作用**

它让握手变成**可验证的**。中断期间外部世界可能已变化（他人推送代码、依赖更新），如果复验发现 Fact 不再成立，这本身就是关键情报——而非一次失败。

### [2025] 与 notes 的关系定为「单向引用」

**决策**

- 本技能 standalone，不要求先有笔记。
- 交接文档可用指针引用已有笔记（带状态标签，如 `.agents/notes/proposed/...`），但不抄正文。
- 本文件是临时耗材，不应被其他任何文档引用。

**放弃的选项**

| 选项 | 放弃理由 |
| :--- | :--- |
| 在 handoff 纪律中写「notes 不得引用 handoff」 | **约束错位**：handoff 的 SKILL.md 控制不了 notes 的写法，执行时 notes 的产出方读不到这条约束 |
| 完全不提 | 单向关系本身值得显式声明，避免未来出现循环引用 |

改为在 handoff 侧写一句弱提示即可覆盖实际风险。

---

### [2025] 参数缺省不追问

**决策**

`argument-hint` 改为可选语气。未传参时（常态），Agent 从会话推断目标并标为 `[Pending / Unverified]`，**不得因为参数缺失而停下来追问用户**。

**理由**

追问的时机（上下文将满）正是用户最不该被打断的时刻，且他大概率也没有答案。

## 3. 明确不做的三件事

| 项 | 理由 |
| :--- | :--- |
| tmp 文件生命周期提示（「接棒确认后可删」） | 纯文档噪音。`/tmp` 由 OS 管理，用户不会因读到提示就去手动清理。若真要解决，位置在接手协议而非技能本体 |
| 在文档中写出未来的 Planner → Worker 技能名 | 会造成悬空引用。在专用技能真正落地前，只声明「不属于本技能范围」 |
| 强制自检报告 | 自检纪律已内置，但输出一份「自检报告」会让文档变重，与「宁可短」冲突 |

---

## 4. 已知残余风险（已接受）

| 风险 | 说明 |
| :--- | :--- |
| **质量完全依赖当次提炼** | standalone + 不强制笔记，复杂任务中断后，决策可能只存在于会话里。这是 A/C 定位的固有代价，用 No Fabrication 换「少传错」 |
| **tmp 无自动清理** | 已判定为非阻塞 |

## 附：本档案的维护约定

- **顶部「当前定位」是活文档**，每次调整后重写为最新结论。
- **下方决策记录只追加**，并被显式视为已废弃结论。
- 阅读顺序是**先现状、后历史**——有疑问再往下挖，不必通读全篇。
